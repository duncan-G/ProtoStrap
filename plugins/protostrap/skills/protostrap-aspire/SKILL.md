# ProtoStrap with Aspire

The AppHost is the application. `aspire run` runs it locally; the `protostrap-spec` pipeline
step writes `protostrap.yaml` from it, joined with the MSBuild project graph. Nothing below
the spec knows Aspire exists.

The design is `docs/protostrap-aspire.md` and the API `hosting/README.md`, at the version in
`WithVersion(...)`. Spec fields are explained in the protostrap-spec skill; code rules in
protostrap-contract.

## The loop

1. **Edit the AppHost** (`Program.cs`), a project reference, or a `Directory.*.props`.
2. **Regenerate:**

   ```bash
   aspire do protostrap-spec
   ```

   Without the Aspire CLI: `dotnet run --project <apphost.csproj> -- --operation publish --step protostrap-spec`.
   With `protostrap` on `PATH`, the step also runs `protostrap check`.
3. **Read the diff** of `protostrap.yaml`, and say in the pull request what it does: new
   `uses` are new permissions, new `sources` new rebuild triggers, new queues and buckets an
   infra change (protostrap-spec's "What a change does").
4. **Commit the spec with the change.** The reusable `plan` workflow, given `apphost:`,
   regenerates it and fails when the committed one differs. Give the application's own CI the
   same check (protostrap-setup's templates), so a pull request fails before merge.

**Never edit `protostrap.yaml` by hand.** When the AppHost describes something ProtoStrap
can't run, the step writes nothing and lists every problem with the resource at fault; fix
the AppHost. When the spec is written but `protostrap check` then fails, the file has
changed on disk: fix the AppHost and regenerate before committing.

## The environment

```csharp
var protostrap = builder.AddProtoStrapEnvironment("protostrap", app: "shop")
    .WithVersion("0.1.1")                   // = the workflows' @v0.1.1 and the roots' ?ref=v0.1.1
    .WithIngressPool(vm: "c8g.medium")
    .WithGeneralPool(vm: ["m7g.large", "m6g.large", "m8g.large", "m7gd.large"], min: 1, max: 4)
    .WithComputePool(vm: ["c7g.large", "c6g.large", "c8g.large", "c7gd.large"], min: 0, max: 2)
    .WithDataPool(vm: "m7g.large");
```

`WithSpecPath(...)` and `WithCheck(...)` are optional.
Under `aspire run` the environment is dev, and its secret `shop/dev`: every component's
process gets `SECRET_ID`, `SECRET_PREFIX`, `AWS_REGION` and `AWS_PROFILE` (the AppHost's, or
`developer`), and reads it as in an account once the developer has run `aws sso login`.
Containers take Aspire's parameters locally, so dev's secret holds none of their keys
(docs/secrets.md#dev).

## The tunnel, the gateway and telemetry

```csharp
var gateway = protostrap.AddEnvoyGateway("gateway")
    .WithHost("shop", "shop.example.com", local: "shop.dev.localhost");
protostrap.AddCloudflareTunnel("tunnel", gateway);
protostrap.AddTelemetry("telemetry");
```

Each is the spec's section of that name, at most once per environment, and runs only when
added (protostrap-spec's "The tunnel, the gateway and telemetry"). Without the gateway no
service gets requests from outside the overlay, and nothing gets `HOST_`/`ORIGIN_`; without
the tunnel nothing reaches the gateway from the internet; without telemetry replicas'
output goes to CloudWatch Logs and no `OTEL_` variable is set.

- `WithHost("shop", "shop.example.com", local: "shop.dev.localhost")` names a host: routes
  refer to it as `shop/`, each account's Terraform root may give `shop` another hostname,
  and under `aspire run` every resource gets `HOST_SHOP` and `ORIGIN_SHOP` for the local one.
- `gateway.WithUpstream(api, u => u.Routes("shop/api/"))` sends a service requests ("What
  becomes what"). Calling it again for the same service adds to it.
- `gateway.WithRequest(cpu:, memory:)` sizes the edge, 500m and 256Mi by default, cloudflared
  included; `WithLocalPort(port)` moves the local gateway off 20000.
- `AddTelemetry(...)` takes `.WithRequest(cpu:, memory:)`, `.WithVolume("30Gi")` and
  `.WithRetention(logs:, traces:, metrics:)`, `TimeSpan`s in whole days. The spec gets only
  what is set, else `telemetry: {}`.

## Every compute resource says its kind

| Call                                | Kind     | Settings                                                     |
| ----------------------------------- | -------- | ------------------------------------------------------------ |
| `PublishAsProtoStrapService(s => …)` | service | `Pool`, `Request`, `Ready`, `Metrics`, `Stop`, `Scale`, `SecretFiles`, `SecretPrefix`, `OnConfigChange` |
| `PublishAsProtoStrapWorker(w => …)`  | worker  | `Pool`, `Request`, `Metrics`, `Stop`, `Scale`, `SecretFiles`, `SecretPrefix`, `OnConfigChange` |
| `PublishAsProtoStrapStateful(s => …)` | stateful | `Vm`, `Request`, `Volume`, `Backup`, `Command`, `Metrics`, `Stop`, `SecretFiles`, `SecretPrefix`, `OnConfigChange` |
| `PublishAsProtoStrapTask(t => …)`    | task    | `Pool`, `Request`, `Stop`, `SecretFiles`, `SecretPrefix`     |

An image that can't read the environment's secret, such as Keycloak's or an upstream one,
calls `SecretFiles()`: each key in its `secrets` arrives as `/run/secrets/<KEY>` for its
entrypoint to read. `SecretFiles(SecretChange.Reload)` or `SecretFiles(SecretChange.Run(...))`
takes a new value without replacing the replicas.

A compute resource without one fails generation, and `Request` is required: there is no
default. `Scale` is optional, but without it a service or worker runs exactly one replica,
and a worker never goes to zero. Set `Stop` too: the default, 10 s, ends with the drain.
The callbacks run only in publish mode, so `aspire run` is unchanged.

```csharp
// Each component reads only its connection strings, so its secret holds one key per connection.
const ReferenceEnvironmentInjectionFlags connectionStringOnly =
    ReferenceEnvironmentInjectionFlags.ConnectionString | ReferenceEnvironmentInjectionFlags.ServiceDiscovery;

var postgres = builder.AddPostgres("postgres")
    .PublishAsProtoStrapStateful(s => s.Vm("data-1").Request(cpu: "1000m", memory: "2Gi").Volume(size: "20Gi"));
var db = postgres.AddDatabase("shop-db", databaseName: "shop");

var files  = builder.AddProtoStrapFiles();
var orders = builder.AddProtoStrapQueue("orders");
var docs   = builder.AddProtoStrapBucket("documents", browser: true, versions: TimeSpan.FromDays(7), locked: true);

var migrations = builder.AddProject<Projects.Shop_Migrations>("migrations")
    .WithReferenceEnvironment(connectionStringOnly)
    .WithReference(db, connectionName: "shop").WaitFor(db)
    .PublishAsProtoStrapTask(t => t.Request(cpu: "250m", memory: "256Mi"));

var api = builder.AddProject<Projects.Shop_Api>("api")
    .WithReferenceEnvironment(connectionStringOnly)
    .WithReference(db, connectionName: "shop").WaitFor(db)
    .WithReference(files).WithReference(orders).WithReference(docs)
    .WaitForCompletion(migrations)
    .WithHttpHealthCheck("/healthz")
    .PublishAsProtoStrapService(s => s
        .Request(cpu: "250m", memory: "256Mi")
        .Stop(TimeSpan.FromSeconds(30))
        .Scale(min: 2, max: 6, demand => demand.Cpu(0.70)));
gateway.WithUpstream(api, u => u.Routes("shop/api/"));

builder.AddProject<Projects.Shop_OrdersWorker>("orders-worker")
    .WithReferenceEnvironment(connectionStringOnly)
    .WithReference(db, connectionName: "shop").WaitFor(db)
    .WithReference(orders)
    .PublishAsProtoStrapWorker(w => w
        .Pool(Pool.Compute)
        .Request(cpu: "500m", memory: "512Mi")
        .Stop(TimeSpan.FromSeconds(60))
        .Scale(min: 0, max: 4, demand => demand.Queue(orders, rate: 1, drain: TimeSpan.FromMinutes(1))));
```

`Scale(min, max, demand => …, limits => …)` takes `demand.Cpu(0.70)`, `.Requests(20)`,
`.Queue(queue, rate:, drain:)`, `.Metric(name, target)`, and `limits.Replicas(n)`,
`.Metric(name)`. `AddProtoStrapQueue` also takes `fifo`, `visibility`, `retention` and
`maxReceives`; `AddProtoStrapBucket` takes `browser`, `versions`, `locked` and `expire`.
`AddProtoStrapEmail("email", "shop.example.com")` is the spec's `email` section, and
`.WithReference(email)` puts `email` in a component's `uses`; it does nothing in run mode
(protostrap-email skill).

## What becomes what

| AppHost                                       | Spec                                                         |
| --------------------------------------------- | ------------------------------------------------------------ |
| `AddProject<T>("api")`                        | `project`, and `sources` from the MSBuild reference closure  |
| `AddDockerfile("x", dir)`                     | `build`, `context`, `sources` (minus `.dockerignore`)        |
| `AddContainer("x", image, tag)`               | `image`, stateful only                                       |
| `WaitFor(x)` / `WaitForCompletion(task)`      | `depends_on` / `migrate`                                     |
| `WithReference(queue / bucket / files)`       | `uses` (minus the queue its own `Queue(...)` signal reads)   |
| `WithEnvironment("K", "v")`                   | `env`                                                        |
| `WithEnvironment("K", x.GetEndpoint("http"))` | `env: K: http://x:<port>`, the overlay address               |
| A connection string, a parameter, a connection property | A key name in `secrets`, never a value             |
| `WithHttpEndpoint(targetPort: 8080)`          | `port`                                                       |
| `WithHttpHealthCheck("/healthz")`             | `ready: /healthz`, or `9000/healthz` on another endpoint     |
| `.Ready(Readiness.Grpc.On(9001))`, `Readiness.Tcp`, `Readiness.Command(...)` | `ready: grpc:9001`, `tcp`, `[...]`; workers and stateful too |
| `AddEnvoyGateway`, `AddCloudflareTunnel`, `AddTelemetry` | `gateway`, `tunnel: {}`, `telemetry`                 |
| `gateway.WithUpstream(api, u => u.Routes("shop/api/").Route("/py/", rate: 200))` | `gateway.upstreams.api.routes: [shop/api/, { route: /py/, rate: 200/s }]` |
| `u.Protocol(GatewayProtocol.Http2)`           | `protocol: http2`                                            |
| `u.Authorize(auth, path: "/auth/check", headers: ["x-user"], forward: ["cookie"], respond: ["set-cookie"])` | `authorize`: the gateway asks `auth` about each request first; `auth` needn't be an upstream |
| `u.Authorize(auth, open: true, timeout: TimeSpan.FromMilliseconds(500), skip: ["/assets/", "*.js"])` | `open`, `timeout: 500ms`, `skip`: requests `auth` can't answer for go on anonymously, and static files aren't asked about |
| `.WithProtoStrapSources(":(glob)protos/**")`  | More `sources`, for inputs MSBuild can't see                 |
| `.WithProtoStrapConfig("../config/x", "/etc/x")` | `config`: files it reloads, a read-only bind mount under `aspire run` |
| `.OnConfigChange(ConfigChange.Reload)` or `ConfigChange.Run(...)` | `on_config_change`                         |
| `.WithProtoStrapConfigure(task)`              | `configure`: config applied through its API once it is ready (an identity provider's realms) |
| `.SecretPrefix("Idp_")`                       | `secret_prefix`, so a configure task reads its component's keys |

## Secrets

- `WithReference(db)` adds the connection string **and** Aspire 13's connection properties
  (`SHOP_HOST`, `SHOP_DATABASENAME`, …), each a key in `secrets`. To keep one key per
  connection, give each component
  `WithReferenceEnvironment(ReferenceEnvironmentInjectionFlags.ConnectionString | ReferenceEnvironmentInjectionFlags.ServiceDiscovery)`
  (the `connectionStringOnly` above).
- PostgreSQL and Redis get their generated passwords as secret files with a rotation hook.
  Set them under the resource's prefix, `Postgres_POSTGRES_PASSWORD` and
  `Redis_REDIS_PASSWORD` for resources named `postgres` and `redis`, with connection strings
  that carry them, before the first deploy (protostrap-secrets skill).

## Telemetry

- **ServiceDefaults.** Its `ConfigureOpenTelemetry` exports logs, traces and metrics over
  OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set, which ProtoStrap does in every replica when
  the AppHost calls `AddTelemetry`, as `aspire run` does locally. If `AddServiceDefaults`
  also adds a console logger then, every line arrives twice: clear the console under
  ProtoStrap with the endpoint set instead (protostrap-telemetry's `references/dotnet.md`).
  Without `AddTelemetry` the console stays: stdout is what reaches CloudWatch Logs. Register
  each custom `Meter` and `ActivitySource` there too.
- The name `telemetry` is ProtoStrap's: no compute resource or bucket may take it.

## Run mode

- **With a gateway, `aspire run` runs it** as a container named by its resource name
  (`gateway`): the Envoy an account runs, serving `http://<local hostname>:20000` with each
  upstream's routes and authorizer. The tunnel and telemetry don't run locally: the
  dashboard has the telemetry. The gateway renders with the `protostrap` that
  `protostrap-build`, under it on the dashboard, builds with Go from the ProtoStrap checkout
  the AppHost references, so the machine needs Go at the version ProtoStrap's `go.mod`
  names. Don't add a gateway of the application's own for local routing: test routes
  through this one.
- **When `protostrap-build` says `Behind`,** ProtoStrap's Go changed since it built: use its
  Rebuild command (or restart the gateway) for the gateway to pick it up. `Build failed` has
  Go's output in its console.
- **If the gateway or the spec step warns that `protostrap` "isn't the AppHost's ProtoStrap",**
  that's a binary the AppHost didn't build (on `PATH`, or named by `WithCheck`): rebuild it with
  the `go build` command the warning gives. Until then it behaves as that older ProtoStrap.
- **Open the app from the gateway's links** on the dashboard (one per host), not a service's
  own URL, which skips routing and authorization. Its console logs each request with the
  service it went to and Envoy's response flags: `UAEX` means the authorizer refused it, `NR`
  that no route matched, `UH` that no replica was ready.
- With a gateway, every resource gets `HOST_<NAME>` (the local hostname) and `ORIGIN_<NAME>`
  (`http://<local hostname>:20000`, or the `WithLocalPort` port).

- Queues and buckets are created in one LocalStack container, `protostrap-localstack`, and
  `WithReference` sets `QUEUE_<NAME>_URL`, `BUCKET_<NAME>`, `FILES_BUCKET`, `AWS_REGION`,
  `AWS_ENDPOINT_URL_SQS` and `AWS_ENDPOINT_URL_S3` to it.
- **Credentials aren't set.** Give components that use AWS LocalStack's test credentials in
  run mode only, so the SDK doesn't sign with yours:

  ```csharp
  builder.ExecutionContext.IsRunMode
      ? resource.WithEnvironment("AWS_ACCESS_KEY_ID", "test").WithEnvironment("AWS_SECRET_ACCESS_KEY", "test")
      : resource;
  ```

- S3 clients need path-style addressing against LocalStack. `expire` and `browser` only apply
  in an account.

## What generation rejects

- An image without a tag, or `latest`.
- A service or worker from an upstream image with no Dockerfile; a JavaScript or Python app
  without a Dockerfile of its own in the repository (Aspire's generated one isn't).
- Bind mounts (other than `WithProtoStrapConfig`'s), container runtime arguments,
  `WithEntrypoint`, `WithReplicas` (use `Scale`).
- `WaitForCompletion` of a configure task: wait for the component it configures instead.
- An `AddExecutable` not excluded from publish, or a variable that refers to an excluded resource.
- A volume on a service, worker or task; more than one on a stateful component.
- A Dockerfile not named `Dockerfile`, with build arguments, a target stage, or outside the repository.
- A secret written where it can't be a key in `secrets`: a stateful component's environment,
  or a command argument.
- A project with no `global.json` at or above it pinning `sdk.version`.
- `WithUpstream` of anything but a service published with `PublishAsProtoStrapService`, or
  with no routes; a route naming a host the gateway lacks, or a hostname.
- A `Requests` signal on a service that isn't an upstream; `Readiness.Command` on an
  upstream; `Readiness.Grpc` on an upstream with `GatewayProtocol.Http1`.

Dev-only resources (pgAdmin, smtp4dev, seeders) get `.ExcludeFromManifest()`, or aren't
added when `builder.ExecutionContext.IsPublishMode`. No Envoy or YARP of the application's
own: the gateway is the same in both modes, from its `WithUpstream` calls.

## Warnings worth fixing

The step warns when a project's `ContainerBaseImage` isn't pinned by digest: a patched base
image then changes the build without a commit. Pin it before production.

## Referencing ProtoStrap.Hosting

Until the package is on NuGet, the AppHost references its project from a ProtoStrap checkout
at the same version, through an MSBuild property (`.protostrap/`, where CI checks it out, or
`../ProtoStrap`), with `IsAspireProjectResource="false"`. The package pins an Aspire version
(13.6.2 for 0.1.1): use the same `Aspire.AppHost.Sdk`.
