# protostrap.yaml

`protostrap.yaml`, at the root of the application's repository, is the whole application as
ProtoStrap sees it. Terraform reads it to create AWS and Cloudflare resources, and the
scheduler reads it to run replicas. ProtoStrap knows nothing else about the application.

## Before you edit

1. **Is it generated?** If the file starts with `# Generated by ProtoStrap.Hosting`, never
   edit it. Change the AppHost and regenerate it (protostrap-aspire skill). The deploy
   workflow's `plan` fails when the committed spec differs from what the AppHost writes.
2. **Which version?** `protostrap:` pins ProtoStrap. The docs at that version are the ground
   truth: `.protostrap/docs/protostrap.md#spec` or `../ProtoStrap/docs/protostrap.md#spec` if
   checked out at `v<version>`, otherwise
   `https://github.com/duncan-G/protostrap/blob/v<version>/docs/protostrap.md`. Where they
   and this skill disagree, they win.
3. **One spec or two?** If the workflows pass `spec: protostrap.dev.yaml` (or similar), each
   environment has its own spec. Change every one of them in the same pull request.

Every field, with its kinds and formats, is in [references/fields.md](references/fields.md).
How to pick signals, limits and sizes is in [references/scaling.md](references/scaling.md).
PostgreSQL, Redis and other stateful components, with their volumes, backups and restores,
are in [references/stateful.md](references/stateful.md).

## The parser

ProtoStrap reads a subset of YAML, and refuses the rest rather than guess:

- Block and flow mappings and sequences, plain and quoted scalars, literal (`|`) and folded
  (`>`) block scalars, comments.
- **No** anchors, aliases, tags, merge keys (`<<:`) or multiple documents. Repeat values instead.
- **A key it doesn't know is an error**, so a typo fails `protostrap check` rather than being ignored.
- Keep each item of a command list on one line, quoted if needed, as the sample's
  `on_secret_change` hooks are. Don't make a list item a block scalar.

## Choosing a kind

| Kind       | For                                                                 | Usually runs on                         |
| ---------- | ------------------------------------------------------------------- | --------------------------------------- |
| `service`  | Answers requests: HTTP, gRPC, gRPC-Web. Routed by the edge, or only called by other services | `pool: general`          |
| `worker`   | Takes jobs from an SQS queue. Can sit at zero replicas              | `pool: compute`, which starts in spare room on `general` |
| `stateful` | An upstream image with data on its own EBS volume: PostgreSQL, Redis | A data VM, `vm: data-1`, pinned        |
| `task`     | Runs to completion once per release in which its image changed, before the components that name it in `migrate`: migrations. Or, named in `configure`, after its component is ready, whenever what it applies changes | `pool: general` |

The edge (cloudflared and Envoy) isn't listed: ProtoStrap adds it. Only `edge.request` can be set.
Nor is telemetry: only the `telemetry` section's size and retention (protostrap-telemetry).

**No kind runs on a schedule.** ProtoStrap has no cron: tell the user before building
around it (protostrap-contract's "Work on a schedule").

Services and workers are always **built** from the repository (`build` or `project`). Only a
stateful component runs an upstream `image` as it is. An upstream server such as Keycloak
needs a Dockerfile of its own (`FROM keycloak/keycloak:26.1`, plus its files) to be a service.

## Adding a component

1. **Name** it in lowercase with dashes, at most 40 characters, such as `document-import`;
   not `edge`, `telemetry`, `protostrap`, `scheduler` or `agent`. The name is its DNS name on the overlay
   (`http://document-import:8080`), its ECR repository, log group
   (`/protostrap/<app>/<name>`), IAM role and secret prefix (`DocumentImport_`). A name whose
   prefix would be reserved or invalid (`shared`, `reporter`, one starting with a digit)
   needs `secret_prefix`. Renaming a component makes a new one and removes the old.
2. **Say how it's built.** `build: services/x` is a directory with a file named `Dockerfile`
   (no build arguments, no `--target` stage). `project: src/X/X.csproj` builds with the .NET
   SDK's container publish instead. `context` is the build context when the Dockerfile
   copies from a parent directory.
3. **List its `sources`.** The image tag is a hash of the tracked files in `build` (or the
   project's directory) and `sources`. Anything else the image is built from, such as shared
   libraries, `Directory.Build.props`, `Directory.Packages.props`, `nuget.config`,
   `global.json`, lock files or `.proto` files, must be in `sources`, as directories, files
   or git pathspecs (`":(glob)services/**/Protos/**"`). **A missing source means a change
   there never rebuilds the image.** `protostrap plan` prints each component's sources.
4. **Size its `request`** (`{ cpu: 500m, memory: 512Mi }`). Memory is a hard limit, so a
   replica that goes over it is killed; CPU is a share, so idle CPU still gets used. It must
   fit one VM of its pool after the pool's `reserved`. Measure, then size: see
   [references/scaling.md](references/scaling.md#sizing-a-request).
5. **For a service:** `port`, `ready`, and `routes` if the edge sends it requests. `ready` is
   `grpc`, `tcp` or an HTTP path such as `/healthz`, each optionally on another port
   (`grpc:9001`, `tcp:9001`, `9000/health/ready`), or a command as a list for an unrouted
   service. `protocol` (`http1`, `http2` or `grpc`) is what the edge speaks to it: it defaults
   to `grpc` with `ready: grpc`, otherwise `http1`, and only `grpc` gets browsers' gRPC-Web
   translated. A routed service with a gRPC check needs `http2` or `grpc`. Workers and
   stateful components may have a `ready` too; a worker's names a port or is a command. The
   code must meet the application contract (protostrap-contract skill): a readiness check
   that answers only for its own name, and draining on SIGTERM.
6. **`stop`** is the time from SIGTERM to SIGKILL: at least the drain delay (10 s) plus the
   longest request, or for a worker, the longest job, up to 1 h. **Always set it:** the
   default, 10 s, ends exactly when the drain does, so in-flight requests are killed. On a
   Spot interruption it is cut to 90 s.
7. **`depends_on`** names what must have a ready replica before this one first starts, and
   orders secret rotations. Never a cycle, and never a task: a task is run with `migrate` or
   `configure`. What it depends on must also have run its configure task, if it has one.
8. **`uses`** names every queue it sends to or receives from, every bucket it reads or
   writes, `files` or `backups` for ProtoStrap's buckets, and `email` to send mail
   (protostrap-email). **Its IAM role is built from `uses`**: forget one and the code gets
   AccessDenied in an account, while it works locally. Nothing else can go in it: **the
   spec can't grant another AWS API** (a model on Bedrock, DynamoDB, KMS…). Every role is
   held inside a boundary that only an Org Admin widens, in bootstrap's
   `extra_role_actions`, and ProtoStrap has no field to give one component more. Tell the
   user before writing code that needs it.
9. **`env`** for plain values. **Never a secret.** Secret keys are named in `secrets`, and
   their values live in the environment's secret (protostrap-secrets skill). A key can't be
   in both, and `env` can't set what ProtoStrap sets: `PROTOSTRAP_*`, `AWS_*`, `SECRET_*`,
   `QUEUE_*_URL`, `BUCKET_*`, `FILES_BUCKET`, `BACKUPS_BUCKET`.
10. **`migrate`** names a task (or is a command in this component's image) to run before its
    first new replica in a release. Migrations must stay compatible with the previous release.
11. **`scale`** for services and workers: `min`, `max`, `demand`, and `limits` if any.
    Without it a component runs exactly one replica, and a worker never goes to zero.
    A `requests` signal needs `routes`: the edge counts them.
12. **`metrics: 9090/metrics`** if a `metric` signal or limit reads its Prometheus endpoint.
13. **Config.** Decide by how the program reads it ([docs/config.md](https://github.com/duncan-G/protostrap/blob/v<version>/docs/config.md)
    at the spec's version):
    - **Read once at start or build** (providers, themes, a bootstrap file): in the image.
    - **Files it watches or reloads**: `config: { from: config/<name>, path: /etc/<name> }`,
      with `on_config_change: reload`, or a command that checks the files and then reloads,
      so bad files fail the release. Never a secret in them: they point at `/run/secrets/<KEY>`.
    - **Kept in its database, changed through its API** (an identity provider's realms):
      `configure: <task>`, a task that applies the whole config declaratively, every run, and
      logs in with a key from the environment's secret. Never a manual step on a VM, and never
      a startup import that skips what exists.

## Routes

- `shop/api/` matches one host, by its name in `hosts`, and a path prefix. `/api/` alone
  matches every host.
- **`hosts` names each host with its hostname** (`shop: shop.example.com`). Routes name the
  host, never the hostname, so they mean the same in every account; each account's
  Terraform root may give every name its own hostname (`hosts = { shop = "shop.dev.example.com" }`),
  and must then give one to every name. Replicas get `HOST_<NAME>` and `ORIGIN_<NAME>`
  (`https://…`): build redirect URLs, cookie domains and allowed origins from them, never
  from a hostname in code or `env`.
- Two routes matching the same host and path are rejected.
- **`authorize: { by: auth, path: /auth/check, headers: [x-user], forward: [cookie] }`** has
  the edge ask `auth` about each request to this service's routes first. A 2xx lets it
  through with `x-user` from the answer (the client's own `x-user` is removed first);
  anything else is the response. Use it for sessions a sign-in service keeps, rather than
  checking a cookie in every service. The authorizer's code is protostrap-contract's
  "An authorizer".
- `{ route: /py/, rate: 200/s }` rate-limits a route at the edge.
- External clients can't use native gRPC through the tunnel. They use gRPC-Web, which Envoy
  translates for `protocol: grpc` services (any other service gets it as sent), or HTTP/JSON
  endpoints the service serves itself. Services call each other with
  native gRPC on the overlay.
- The edge gives a response 120 s, then cuts it, streams included.
- **No WebSockets:** Envoy's routes don't upgrade connections. Server-sent events and other
  long responses are cut at 120 s too, so a client that streams must reconnect.

## Queues and buckets

- **Every queue** named in a `uses` or a `queue` signal is listed under `queues`, with
  `visibility` (default 2m, longer than the longest job), `retention`, `max_receives` and
  `fifo`. It becomes `protostrap-<name>` with a dead-letter queue.
- **Every bucket** but `files` is listed under `buckets`: `browser`, `versions`, `lock`
  (needs `versions`, can't be undone) and `expire`, in whole days (`30d`). Names are at most
  24 lowercase letters, digits and dashes. `files`, `backups`, `deploy`, `tfstate` and
  `telemetry` are ProtoStrap's, and a bucket can't share a queue's name.
- The code finds them in `QUEUE_<NAME>_URL`, `BUCKET_<NAME>` and `FILES_BUCKET`. `<NAME>` is
  the name in upper case with `-` as `_`: queue `document-upload` is `QUEUE_DOCUMENT_UPLOAD_URL`.

## Removing things

- **A bucket removed from the spec is deleted.** In production, where `force_destroy` is
  off, the apply fails unless it's empty. To keep it, add it to `retired_buckets` in every
  account's Terraform root, with the settings it had.
- **A removed component or queue** should go into `retired_components` or `retired_queues`
  in each root for at least one release, so rolling back still finds its repository, role
  and queued jobs. `retired_queues` assumes a standard queue: a retired FIFO queue is replaced.
- **A stateful component's volume is never deleted by Terraform.** Removing or renaming the
  component fails the infra plan until an Org Admin forgets the volume with
  `terraform state rm` in each account ([references/stateful.md](references/stateful.md#changing-one)).
- **A volume's `size` only grows.** Size PostgreSQL's for a year of data.

## What a change does

Say this in the pull request, so the reviewer knows what merging restarts or provisions:

| A change to                                                         | Does                                                         |
| ------------------------------------------------------------------- | ------------------------------------------------------------ |
| A component's sources                                               | Builds its image, replaces its replicas a quarter at a time  |
| `request`, `port`, `ready`, `stop`, `env`, `command`, `metrics`, `secrets`, `secret_prefix`, `secret_files`, `on_secret_change`, `backup`, the volume's `path`, `config`'s `path`, `on_config_change` | Replaces its replicas |
| A file in a component's `config.from`                               | With `on_config_change: restart`, replaces its replicas; with `reload` or a command, swaps the files in a quarter of its replicas at a time, no restart |
| A configure task, its config or keys, or the component it configures | Runs the task once, after the component has rolled out     |
| A stateful component's `image` or replica settings                  | Stops it, then starts the new one: **brief downtime**        |
| `routes`, `protocol`                                                | Reloads the edge's routes, no restart                        |
| `scale`, a pool's `spare`, `target` or `reserved`                   | Changes counts on the next cycle, no restart                 |
| `uses`, a queue signal's queue                                      | Terraform updates the component's role                       |
| `hosts`, `queues`, `buckets`, a pool's VM types, `min`, `max`, `count`, a volume's `size`, a new component | Terraform first (in prod, after the `prod-infra` approval) |
| `edge`, or `protostrap:`                                            | A new edge starts beside the old; the scheduler and agents update themselves |
| `telemetry`                                                         | Stops the telemetry replica, then starts the new one: nothing is taken in for about a minute |

## Check it

Always run the checker on the result, with the CLI at the spec's version:

```bash
go build -o /tmp/protostrap ./cmd/protostrap   # in a ProtoStrap checkout at v<version>; standard library only, builds offline
```

```bash
/tmp/protostrap check --spec protostrap.yaml
```

```bash
/tmp/protostrap plan --spec protostrap.yaml
```

`check` rejects a request that doesn't fit one VM of its pool after the reserve, stateful
components that don't fit their data VM together, overlapping routes, a `depends_on`, `uses`
or `vm` naming something that doesn't exist, bucket rule breaks, secret names and prefixes it
can't accept, and `depends_on` cycles. `plan` prints each built component's image tag and
sources, so you can see that a shared library is in the sources it should be.

## Never

- Put a secret value in the spec, a comment, or a commit.
- Use an image tag of `latest`, or no tag.
- Shrink a volume, or turn a bucket's `lock` off.
- Give a service that must stay up in production `min: 1`: it needs `min: 2` and a pool of
  at least two VMs (`min` plus `spare`) so a lost VM leaves one replica serving.
